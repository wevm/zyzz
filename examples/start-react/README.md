# React + TanStack Start

```sh
pnpm build
pnpm --dir examples/start-react dev
```

Run from the repository root after `pnpm install`. Vite loads `zyzz/vite` from the built package; `pnpm examples` runs the same steps for every example.

`vite.config.ts` places the `zyzz()` plugin beside TanStack Start and the React plugin. The plugin compiles every route and component module during `vite dev` and `vite build`, for the client and the server environment alike:

```ts
import { tanstackStart } from '@tanstack/react-start/plugin/vite'
import react from '@vitejs/plugin-react'
import { defineConfig } from 'vite'
import { zyzz } from 'zyzz/vite'

export default defineConfig({
  plugins: [zyzz(), tanstackStart(), react()],
})
```

The application renders on the server. `vite build` emits the client assets under `dist/client` and a fetch handler at `dist/server/server.js`; the TanStack Start hosting guide covers wrapping that handler for Node.js or a platform. There is no static site to publish, so `package.json` sets `config.site` to `false` and the Examples workflow builds the example without a deployment.

## Document Shell

TanStack Start renders the document from `src/routes/__root.tsx` rather than an `index.html`, so the Vite plugin cannot inline initialization for it. The root route adds the configuration's `script()` and the `zyzz/reset.css` link through its `head()` option, and `HeadContent` places both before the route styles and scripts. The script changes root classes before hydration, and `<html suppressHydrationWarning>` accepts that difference.

```tsx
import reset from 'zyzz/reset.css?url'
import { script } from '../zyzz.config.js'

export const Route = createRootRoute({
  component: RootComponent,
  head: () => ({
    links: [{ href: reset, rel: 'stylesheet' }],
    scripts: [{ children: script() }],
  }),
})
```

Module stylesheets travel with the routes: TanStack Start links the styles of each rendered route from the server, so the first response carries the compiled CSS without a flash. `src/App.tsx` reads `appearance.get()` after hydration in an effect, because the server render has no document, and persists changes with `appearance.set()`.

`src/routeTree.gen.ts` is generated by the TanStack Router plugin during `vite dev` and `vite build` and is not committed.

## Feature Map

| Source                  | Capabilities                                                                                     |
| ----------------------- | ------------------------------------------------------------------------------------------------ |
| `src/zyzz.config.ts`    | Named themes, light/dark pairs, extensions, tokens, aliases, property-specific scales, layers    |
| `src/routes/__root.tsx` | `head()` with the inline `script()` and reset stylesheet, hydration-safe root markup             |
| `src/App.tsx`           | Root theme and scheme on `<html>` via `appearance`, nested scopes, global CSS in a named layer   |
| `src/Styling.tsx`       | Literal reuse, object spread, fallbacks, importance, token/variable references, state, overrides |
| `src/Dynamic.tsx`       | Typed runtime inputs, `variable()`, registration, static and inline `variables`                  |
| `src/Relationships.tsx` | Empty `css()`, `selectors`, hover, data attributes, nth-child, sibling selectors, `:has()`       |
| `src/Motion.tsx`        | Local/imported keyframes, starting styles, reduced motion                                        |

See [Vite Setup](../../docs/introduction/vite.md) and the [`zyzz/vite` reference](../../docs/api/vite/zyzz.md).
