# Recipe

Serialize finite variant selections as data attributes beside compiled class names.

The compiler rewrites each [`variants`](/docs/api/core/variants) definition without conditions or dynamic choices into a `Recipe.create` call. Applications normally do not import it. The compiled rules match the returned `data-*` attributes, so a selection never adds a class.

```ts title="button.ts"
import { Recipe } from 'zyzz/runtime'

// [!code hl:5]
// Rules match `[data-size="small"]` and `[data-size="large"]`
const button = Recipe.create({
  axes: { size: ['small', 'large'] },
  className: 'z-button',
  defaults: { size: 'small' },
})

// { className: 'z-button', 'data-size': 'large' }
export const props = button({ size: 'large' })
```

## Signature

```ts
// Generated metadata for one variants definition
Recipe.create(options)
```

## Parameters

### options.axes

- **Type:** `{ [axis: string]: readonly string[] }{:ts}`

Each axis and its choices, in authored order. Boolean choices appear as `'true'` and `'false'`.

```ts /axes: { size: ['small', 'large'] }/
// One axis with two choices
Recipe.create({
  axes: { size: ['small', 'large'] },
  className: 'z-button',
  defaults: {},
})
```

### options.className

- **Type:** `string{:ts}`

The complete generated class list, including every variant rule's class.

```ts /className: 'z-button'/
// Every selection returns the same class list
Recipe.create({ axes: {}, className: 'z-button', defaults: {} })
```

### options.defaults

- **Type:** `{ [axis: string]: string | null }{:ts}`

The choice used when an axis is omitted or `undefined`. An axis without a default stays unselected.

```ts /defaults: { size: 'small' }/
// An omitted size selects small
Recipe.create({
  axes: { size: ['small', 'large'] },
  className: 'z-button',
  defaults: { size: 'small' },
})
```

### options.html

- **Type:** `boolean{:ts}`
- **Default:** `false{:ts}`

Return HTML attributes, with `class` and a serialized `style`, through [`Html.from`](/docs/api/runtime/namespaces/Html#htmlfrom). Configurations with `output: 'html'` set it.

```ts /html: true/
// { class: 'z-button', 'data-size': 'small' }
Recipe.create({
  axes: { size: ['small'] },
  className: 'z-button',
  defaults: { size: 'small' },
  html: true,
})()
```

## Application

The returned callable accepts the [`variants`](/docs/api/core/variants#application) application options. Selections are not validated at runtime, since TypeScript and the compiler already check them.

### options[axis]

- **Type:** `string | boolean | null | undefined{:ts}`
- **Default:** `options.defaults[axis]{:ts}`

The selected choice. `null` clears the axis, overriding its default.

```ts /size: null/
// { className: 'z-button' }
button({ size: null })
```

### options.style

- **Type:** `style.Options['style']{:ts}`
- **Default:** `undefined{:ts}`

Inline overrides, merged with `options.className` and `options.vars` as [`Props.create`](/docs/api/runtime/namespaces/Props#application) merges them.

```ts /style: { padding: '24px' }/
// Adds style: { padding: '24px' }
button({ style: { padding: '24px' } })
```

## Returns

### className

- **Type:** `string{:ts}`

The generated class list, followed by `options.className` when supplied. HTML output names it `class`.

```ts /props.className/
// 'z-button'
props.className
```

### data-[axis]

- **Type:** `string{:ts}`

The selected choice of each axis, converted to a string. A cleared or unselected axis has no attribute.

```ts /props['data-size']/
// 'large'
props['data-size']
```

### style

- **Type:** `Readonly<Record<string, string | number | undefined>> | undefined{:ts}`

The merged inline styles, present only when the call supplies overrides. HTML output serializes it to a string.

```ts /style/
// { padding: '24px' }
button({ style: { padding: '24px' } }).style
```

## Types

- **`Recipe.create.Options{:ts}`:** The `{ axes, className, defaults, html? }` input.
- **`Recipe.Definition{:ts}`:** Metadata shared with [`PayloadRecipe`](/docs/api/runtime/namespaces/PayloadRecipe), adding `conditions`, `defaultPayloads`, and `payloads`.
- **`Recipe.Payload{:ts}`:** One dynamic choice, with its `axis`, `choice`, and ordered `slots`.

```ts title="payload.ts"
import type { Recipe } from 'zyzz/runtime'

// [!code hl:2]
// Base slots first, then one record per condition
export const payload = {
  axis: 'size',
  choice: 'custom',
  slots: [{ padding: '--size-padding' }, { padding: '--size-padding-wide' }],
} satisfies Recipe.Payload
```

## Errors

`Recipe.create` throws no errors and adds no runtime validation. Unknown choices are rejected by TypeScript and the compiler before the callable runs.
