# CSS Output

Choose how Zyzz groups declarations in the generated CSS.

## Overview

`cssOutput` selects atomic or grouped CSS. Both modes compile ahead of time. Connect a compiler through [Getting Started](/docs/introduction/getting-started).

Start with atomic. Neither mode guarantees smaller or faster output, so compare CSS, JavaScript, and markup sizes for the application. The [benchmarks](/docs/introduction/benchmarks) use grouped output.

Set the mode in the config, then import its helpers into components. The separate `output` option controls React or HTML props independently of `cssOutput`, as described in the [config reference](https://github.com/wevm/zyzz/blob/main/docs/api/core/Config/create.md).

```ts title="zyzz.config.ts"
import { defineConfig } from 'zyzz'

export const { style, variants } = defineConfig({
  cssOutput: 'grouped',
})
```

## Compare Generated CSS

The same component works in either mode. The setting applies to config-bound helpers, so imports from `zyzz` still use atomic output. There is no per-style override.

```tsx title="Card.tsx"
import { style } from './zyzz.config.js'

export function Card() {
  return (
    <article {...styles.card()}>
      <span {...styles.label()}>Account</span>
    </article>
  )
}

namespace styles {
  export const card = style({ color: 'red', padding: '8px' })
  export const label = style({ color: 'red' })
}
```

Atomic output can share the color class between the card and label.

```css title="Atomic output, illustrative"
.z-text-red {
  color: red;
}
.z-p-8px {
  padding: 8px;
}
```

Grouped output gives each style its own block.

```css title="Grouped output, illustrative"
.z-X8T0-w-styles-card {
  color: red;
  padding: 8px;
}
.z-X8T0-w-styles-label {
  color: red;
}
```

## Generated Names

Common declarations use readable utilities, while contextual declarations use authored names and ordered slots. Variables follow authored paths, such as `--z-color-brand`. Apply returned props rather than copying class names.

Utility and variable names contain no hashes. Contextual classes and inferred selector identities include a stable six-character hash of the module path, so modules can share a config and use the same `namespace styles` member names without collisions. Explicit style IDs remain consumer-owned.

When combining independent configs, supply distinct `defineConfig({ id })` values. The ID prefixes classes, variables, and theme scopes. The compiler reports incompatible generated names when it can detect them, and consumers own collision avoidance across separate stylesheets.

## Preserve the Cascade

Both modes preserve CSS cascade behavior, and declarations share classes only when reuse preserves precedence. Combine styles with `cx`, since multiple JSX spreads can replace styling props.

```tsx title="CompactCard.tsx"
import { cx } from 'zyzz'
import { style } from './zyzz.config.js'

export function CompactCard() {
  return <article {...cx(styles.card(), styles.compact())}>Account</article>
}

namespace styles {
  export const card = style({ color: 'red', padding: '8px' })
  export const compact = style({ padding: '4px' })
}
```

Here, the later padding wins. `cx` also preserves variable bindings and variant attributes. Class-string order does not determine precedence. See [Override Styles](https://github.com/wevm/zyzz/blob/main/docs/guides/styling.md#override-styles).

Global rules, keyframes, and variable scopes keep their CSS structures. Dynamic values bind to precompiled custom properties. Applying styles never inserts CSS rules.

## Deliver Matching Artifacts

Rebuild CSS and generated code together after edits and when changing modes. A config alone does not compile or load styles. Development and production use the same naming rules.

CSS-only builds retain source and require explicit IDs for dynamic styles and other identity-dependent definitions. See [Build & Delivery](/docs/guides/compilation) for setup.

Precompiled libraries retain their output mode. Publish code, declarations, CSS, and compiler metadata from the same build. Consumer config does not change published classes.

## Custom Pipelines

A custom pipeline selects the mode when compiling CSS.

```ts
import { Style } from 'zyzz'
import { Css } from 'zyzz/web'

const styles = Style.define({
  card: { color: 'red', padding: '8px' },
})

const output = Css.compile({ cssOutput: 'grouped', styles })
```

Load `output.css` and apply `output.classes.card`. `Css.compile` has no filesystem or browser side effects. See [Css.compile](https://github.com/wevm/zyzz/blob/main/docs/api/web/Css/compile.md).
