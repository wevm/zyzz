# Stylesheets

Declare global styles, cascade layers, fonts, and animations alongside component styles.

## Overview

Stylesheet helpers from `zyzz/web` contribute CSS during compilation. Use `global` for document selectors, dedicated helpers for rules such as `@font-face`, and returned references for named animations or positioning fallbacks. Component selectors stay inside `style({ selectors: { … } })`.

These are web features. Native font loading and animations need platform-specific behavior. Compiler support also does not establish browser support for an at-rule, so check [Compatibility](/docs/introduction/compatibility) before depending on newer CSS features.

Start with [Getting Started](/docs/introduction/getting-started) to connect compilation. Call helpers at module scope with direct named imports and statically analyzable definitions. Calling a helper during rendering does not install a stylesheet, and repeated calls preserve distinct rules in authored order.

```ts title="src/document.ts"
import { global } from 'zyzz/web'

global({
  body: { margin: 0 },
})
```

## Walkthrough

Cascade layers order document defaults below component styles. These steps declare the order, add defaults to the `base` layer, and style a card in the `components` layer.

<Steps>

### Declare Layer Order

Declare the layer order once in the configuration. Import the returned `style` helper to infer the allowed names in component definitions.

```ts title="zyzz.config.ts"
import { defineConfig } from 'zyzz'

export const { style } = defineConfig({
  layers: ['reset', 'base', 'components'],
})
```

### Add Document Defaults

Add a source module for rules that intentionally target the document. `global` accepts a selector map, with grouping rules around selectors where CSS permits them. The compiler validates its raw layer names, but TypeScript does not infer them from the configuration.

```ts title="src/globals.ts"
import { global } from 'zyzz/web'

global({
  '@layer base': {
    body: { margin: 0 },
    'img, video': { maxWidth: '100%' },
    '@media print': {
      nav: { display: 'none' },
    },
  },
})
```

The Vite integration discovers physical project sources under its root, including modules that components never import. Tests, generated output, and dependencies are excluded by default. The standalone host scans its configured source tree. With the compiler API, include the contributing modules in the supplied graph.

Global contributions are eager, including those declared beside lazy components, and survive JavaScript tree shaking. Watching a changed or deleted source replaces or removes its contribution.

### Apply Component Styles

Import the configured `style` helper and nest the card's declarations under the `components` layer.

```tsx title="Card.tsx"
import { style } from './zyzz.config.js'

export function Card() {
  return <article {...styles.card()}>Account</article>
}

namespace styles {
  export const card = style({
    '@layer components': { padding: '1rem' },
  })
}
```

The compiler merges layer constraints from the configuration and global modules into one shared `@layer reset, base, components;` prelude, and rejects contradictory orders. For declarations at the same origin, the cascade ranks the layers as follows.

## Recipes

### Layers Without Config

When only stylesheet ordering is needed, call `layers` at module scope instead of introducing configuration.

```ts title="src/layers.ts"
import { layers } from 'zyzz/web'

layers(['reset', 'base', 'components'])
```

This helper records order but does not bind layer names to a `style` import. The compiler merges it with other layer constraints, and CSS cascade rules still determine precedence.

### Fonts and Motion

Declare `fontFace` with the font's source URL, then use its family in a style. Keep keyframes near the component that owns the animation. The returned reference supplies `animationName` without a handwritten CSS name.

```tsx title="Notice.tsx"
import { style } from 'zyzz'
import { fontFace, keyframes } from 'zyzz/web'

fontFace({
  fontDisplay: 'swap',
  fontFamily: '"App Sans"',
  src: 'url("./app.woff2") format("woff2")',
})

const enter = keyframes({
  from: { opacity: 0 },
  to: { opacity: 1 },
})

export function Notice() {
  return <p {...styles.notice()}>Changes saved.</p>
}

namespace styles {
  export const notice = style({
    animationDuration: '160ms',
    animationName: enter,
    fontFamily: '"App Sans", sans-serif',
    '@media (prefers-reduced-motion: reduce)': {
      animationName: 'none',
    },
  })
}
```

Place `app.woff2` beside this module. Relative URLs belong to their source module, and Vite processes the asset through its CSS pipeline. `fontFace` contributes an eager rule. Reachable keyframes use stable references, while unused local keyframes are omitted.

Keyframe bodies accept declarations only, without nested selectors, queries, or important declarations. The reduced-motion query disables this nonessential animation. The optional [default config](https://github.com/wevm/zyzz/blob/main/docs/api/default.md) provides font stacks, but the application still owns font loading.

### Optional Reset

The reset is disabled by default, and core imports do not install it. Enable it in the web integration.

```ts title="vite.config.ts"
import { defineConfig } from 'vite'
import { zyzz } from 'zyzz/vite'

export default defineConfig({
  plugins: [zyzz({ reset: true })],
})
```

Next.js uses `zyzz(nextConfig, { reset: true })`. The esbuild, Rollup, Webpack, and unplugin adapters accept the same option. Babel accepts it with `target: 'web'` and inserts a CSS import for the consuming bundler. When plugin injection is disabled, import the stylesheet explicitly from the application entrypoint.

```ts title="src/main.ts"
import 'zyzz/reset.css'
```

The reset's declarations live in the `reset` layer, so normal unlayered declarations take precedence regardless of stylesheet load order. Use configured layers when component styles also need an explicit order. The reset applies these defaults:

- Applies border-box sizing.
- Removes margins and padding.
- Removes default heading, link, and list styling.
- Makes form controls inherit typography.
- Makes replaced elements block-level.
- Uses system fallbacks in its document and code font stacks.

### Pages and Transitions

Use dedicated helpers for descriptors and statement rules. `global` owns selectors and grouping rules, rather than `@font-face`, `@page`, or stylesheet imports.

```ts title="src/print.ts"
import { page } from 'zyzz/web'

page({
  descriptors: {
    size: 'A4',
    margin: '2cm',
    '@bottom-center': { content: 'counter(page)' },
  },
})
```

`page` emits an `@page` rule for print, and margin-box rendering depends on the browser or print engine. Use `viewTransition({ navigation: 'auto' })` for a navigation transition rule only when the target browser supports it.

Nested `@media`, `@supports`, `@container`, `@scope`, `@starting-style`, and declared `@layer` keys belong in valid style bodies instead. See the [at-rule reference](https://github.com/wevm/zyzz/blob/main/docs/api/web/at-rules.md) for each helper's grammar and target limits.

### Position Fallbacks

Named helpers return typed references for their intended properties. For example, `positionTry` returns a fallback reference for `positionTryFallbacks`.

```ts title="src/tooltip.ts"
import { style } from 'zyzz'
import { positionTry } from 'zyzz/web'

const above = positionTry({
  positionArea: 'top',
  marginBottom: '0.5rem',
})

export namespace styles {
  export const tooltip = style({
    position: 'absolute',
    positionAnchor: '--trigger',
    positionArea: 'bottom',
    positionTryFallbacks: above,
  })

  export const trigger = style({ anchorName: '--trigger' })
}
```

Apply `styles.trigger()` to the anchor and `styles.tooltip()` to the positioned element. The browser can try the `above` fallback when the initial placement overflows. Anchor positioning requires browser support and an eligible anchor in scope.

### Packed Libraries

Publish transformed modules, declarations, and matching CSS together, and document the stylesheet import that consumers need. Standalone builds load combined `zyzz.css`, or `zyzz.shared.css` before individual module stylesheets. See [Build & Delivery](https://github.com/wevm/zyzz/blob/main/docs/guides/compilation.md#publish-libraries) for the complete publishing workflow.

When consumers compile their own Zyzz sources against the library, keep generated `<entry>.zyzz.json` metadata beside the compiled entrypoints. These sidecars retain global contributions, fonts, keyframes, and layer constraints across imports and re-exports, and source maps preserve the original authoring content. Identical contributions emit once, while conflicting copies fail compilation.

Keep referenced assets with the published output. Source assets resolve relative to their owning module. The standalone host copies local source assets into its output tree, and Vite resolves assets through its CSS pipeline. Packed external asset copying in the standalone host remains unsupported.
