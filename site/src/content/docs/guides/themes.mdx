# Themes & Tokens

Define shared design values, apply named sets to sections of a page, and keep light and dark colors in the same component styles.

## Start with shared values

A token is a named design value, such as `foreground` or `page`. Zyzz stores tokens in variable sets and compiles references to CSS custom properties. Import the configured `style` helper to use those names in components.

The examples below require the compiler setup in [Getting Started](/docs/introduction/getting-started). A variable definition alone does not load its CSS or apply its scope.

```ts title="zyzz.config.ts"
import { defineConfig, defineVars, extendVars } from 'zyzz'

const base = defineVars({
  color: {
    accent: { light: '#2563eb', dark: '#60a5fa' },
    foreground: { light: '#171717', dark: '#fafafa' },
    surface: { light: '#ffffff', dark: '#111111' },
  },
  spacing: { page: '1.5rem' },
})

const alternate = extendVars(base, {
  color: { accent: { light: '#9333ea', dark: '#c084fc' } },
  spacing: { page: '2rem' },
})

export const { appearance, script, style, vars } = defineConfig({
  defaultVars: 'base',
  storageKey: 'app-appearance',
  vars: { base, alternate },
})
```

`defineVars` creates a typed reference tree. `extendVars` replaces existing leaves and retains omitted values. All named sets must have matching paths and compatible value domains. New paths or incompatible overrides fail validation. To use one set, pass `vars: base` and omit `defaultVars`.

## Use tokens in components

Default mappings connect categories to CSS properties. For example, `color` supplies `color` and `backgroundColor`, while `spacing` supplies padding and gap. Explicit references such as `vars.spacing.page` retain their value domain and bypass category lookup.

Properties with configured tokens require a token name or compatible reference. Use ` !custom` for a CSS value outside the scale, such as `padding: '18px !custom'`. The compiler removes the suffix and retains CSS value checking. Properties without configured tokens accept ordinary CSS values.

Configured token names take precedence over CSS literals. If a token is named `red`, `color: 'red'` selects the token, while `color: 'red !custom'` selects the CSS color. Dynamic callbacks cannot choose token names. Use [variants](https://github.com/wevm/zyzz/blob/main/docs/guides/variants.md) for finite token choices.

## Apply a scope

Call `vars` on an enclosing element to select a set. Apply the default at the application boundary, then select alternate sets where needed. The same component styles resolve against the nearest enclosing variable scope.

<Tabs label="ThemePreview.tsx">

<Tab title="ThemePreview.tsx">

```tsx title="ThemePreview.tsx"
import { Card } from './Card.js'
import { vars } from './zyzz.config.js'

export function ThemePreview() {
  return (
    <main {...vars()}>
      <Card />
      <section {...vars({ set: 'alternate' })}>
        <Card />
        <section {...vars({ set: 'base' })}>
          <Card />
        </section>
      </section>
    </main>
  )
}
```

</Tab>

<Tab title="Rendered">

<Examples.Scopes />

</Tab>

</Tabs>

The first card uses base values, the second uses alternate values, and the nested card returns to base values. Scope selection returns styling props and emits no new CSS rules. `vars()` selects the configured default. Omitting `set` also selects that default, rather than inheriting an alternate set.

Omitting `colorScheme` inherits the surrounding scheme. A single-set configuration accepts a scheme but no `set` option. These web scopes rely on CSS inheritance. See [React Native](https://github.com/wevm/zyzz/blob/main/docs/guides/native.md) for native theme selection and target limitations.

## Select a color scheme

Define scheme-dependent colors as complete `{ light, dark }` pairs. A plain color value stays the same in both schemes. Select the scheme independently of the variable set.

import { Card } from './Card.js'
import { vars } from './zyzz.config.js'

export function DarkPreview() {

Use `light` or `dark` to fix a scheme. Use `light dark` to follow the browser's preferred scheme. Selecting `alternate` changes the accent and spacing, while selecting `dark` changes the foreground and surface pair values. Neither selection requires different component definitions.

Typography sets bundle font family, size, weight, letter spacing, and line height. Explicit fields override preset fields in the same block, including conditional fields. Load fonts in the application. The bundled sets do not install fonts or descendant styles.

The `vars` export contains references. The separate `tokens` export contains raw values. Use references when a value should follow a scope or scheme. See the [default config reference](https://github.com/wevm/zyzz/blob/main/docs/api/default.md) for all categories and typography sets.

## Derive semantic values

Keep palette values and their semantic aliases in one set with the second `defineVars` argument. The callback receives references to the base values. Extending a palette leaf then updates the semantic values that reference it within the extended scope.

```ts title="palette.config.ts"
import { defineConfig, defineVars, extendVars } from 'zyzz'

const base = defineVars(
  { color: { palette: { ink: '#171717', paper: '#fafafa' } } },
  (vars) => ({
    color: {
      foreground: {
        light: vars.color.palette.ink,
        dark: vars.color.palette.paper,
      },
    },
  }),
)

const alternate = extendVars(base, {
  color: { palette: { ink: '#2563eb' } },
})

export const { style, vars } = defineConfig({
  defaultVars: 'base',
  vars: { base, alternate },
})
```

The alternate foreground is blue in light mode and retains the paper color in dark mode. Derived callbacks cannot reference other derived values or redefine existing leaves. Keep the callback synchronous with a literal object result so the compiler can extract it.

References to separately defined palettes retain those palettes' identities. Scope those definitions too when they need to change. Use derivation within one set when palette overrides should follow the selected set. [Vars](https://github.com/wevm/zyzz/blob/main/docs/api/core/Vars/README.md) also documents composed CSS values and cycle validation.

## Customize property mappings

Use `mappings` to connect a custom category to CSS properties. Each supplied category replaces its default mapping. Other category mappings stay intact. Shorthands expand local aliases into CSS properties, and each expanded property checks the value.

```ts title="mapped.config.ts"
import { defineConfig } from 'zyzz'

export const { style, vars } = defineConfig({
  mappings: {
    surface: ['backgroundColor'],
    spacing: ['gap', 'padding', 'paddingLeft', 'paddingRight'],
  },
  shorthands: { px: ['paddingLeft', 'paddingRight'] },
  vars: {
    surface: { panel: { light: '#fff', dark: '#171717' } },
    spacing: { page: '1rem' },
  },
})

namespace styles {
  export const panel = style({
    backgroundColor: 'panel',
    px: 'page',
    width: vars.spacing.page,
  })
}
```

Here, `width` uses an explicit reference because the custom spacing mapping only supplies gap, padding, and its left and right longhands. Use `[]` to disable a category's shortcuts or `mappings: false` to require full paths. Dedicated categories, such as `padding`, take precedence over shared `spacing` for the same name.

Avoid mappings that give one property the same name from multiple categories. See [category fallbacks](https://github.com/wevm/zyzz/blob/main/docs/api/core/Vars/README.md#category-fallbacks) for lookup order and [Config.create](https://github.com/wevm/zyzz/blob/main/docs/api/core/Config/create.md#full-variable-paths) for full-path examples.

## Make values responsive

Give a conditional leaf a `default` and ordered media overrides. Every branch must have a compatible value domain. A color branch can also contain a light/dark pair.

```ts title="responsive.config.ts"
import { defineConfig, defineVars } from 'zyzz'

const base = defineVars({
  spacing: {
    page: {
      default: '1rem',
      '@media (min-width: 48rem)': '2rem',
      '@media (min-width: 72rem)': '3rem',
    },
  },
})

export const { style, vars } = defineConfig({ vars: base })

namespace styles {
  export const page = style({ padding: 'page' })
}
```

At matching widths, the last authored matching declaration wins. The browser evaluates precompiled media rules. Media-conditioned variable values require the web target. `extendVars` replaces a conditional leaf as a whole, so include every branch that the override should retain.

## Name queries

Query aliases describe compile-time thresholds. Define `breakpoint` for media queries, `container` for container queries, and `containerNames` for named containers.

```ts title="queries.config.ts"
import { defineConfig } from 'zyzz'

export const { style } = defineConfig({
  vars: {
    breakpoint: { tablet: '48rem' },
    container: { card: '20rem' },
    containerNames: ['preview'],
  },
})

namespace styles {
  export const container = style({
    containerName: 'preview',
    containerType: 'inline-size',
  })

  export const card = style({
    '@media >=tablet': { padding: '2rem' },
    '@container preview card': { display: 'grid' },
  })
}
```

Apply `styles.container()` to an ancestor and `styles.card()` to its child. Runtime set selection does not change query thresholds. Breakpoints and container names have no declaration references. Container values also supply sizing variables. See [Conditions](https://github.com/wevm/zyzz/blob/main/docs/guides/conditions.md) for query syntax.

## Save and restore preferences

Use the `appearance` helper from the first config to update the document root and save a preference. This action affects the root, while `vars` can create local scopes. Preference controls must keep their own application state in sync.

<Tabs label="AppearanceButton.tsx">

<Tab title="AppearanceButton.tsx">

```tsx title="AppearanceButton.tsx"
import { appearance } from './zyzz.config.js'

export function AppearanceButton() {
  return (
    <button
      type="button"
      onClick={() => appearance.set({ set: 'alternate', colorScheme: 'dark' })}
    >
      Use alternate dark colors
    </button>
  )
}
```

</Tab>

`appearance.get()` reads the applied root `{ set, colorScheme }`. `appearance.set()` persists under the config's `storageKey`, which defaults to `zyzz`. If storage is blocked, the selection still applies to the current document. Single-set configs support only color-scheme preferences.

Passing `colorScheme: undefined` clears the scheme selection and persists that cleared state.

Generate `script()` on the server or at build time. Execute the returned JavaScript in a synchronous inline script early in the document head to restore saved preferences before painting. Keep default root props in the server markup.

<Tabs label="Document.tsx">

<Tab title="Document.tsx">

```tsx title="Document.tsx"
import type { ReactNode } from 'react'
import { script, vars } from './zyzz.config.js'

export function Document(props: Document.Props) {
  return (
    <html
      lang="en"
      suppressHydrationWarning
      {...vars({ colorScheme: 'light dark' })}
    >
      <head>
        <script
          nonce={props.nonce}
          dangerouslySetInnerHTML={{ __html: script() }}
        />
      </head>
      <body>{props.children}</body>
    </html>
  )
}

export declare namespace Document {
  type Props = { children: ReactNode; nonce?: string | undefined }
}
```

</Tab>

Use the application's CSP nonce or a hash of the generated source when CSP requires it. Do not add `async`, `defer`, or `type="module"` to this script. Missing, malformed, or inaccessible storage leaves server defaults intact. The helper does not manage hydration or subscribe controls to changes.

For exact storage behavior and framework integration constraints, see [Config Script](https://github.com/wevm/zyzz/blob/main/docs/api/core/Config/script.md).

## Compile without a bundler

For an in-memory stylesheet, compile explicit definitions through `Css.compile`. Load the resulting CSS and apply both the scope class and the component class.

```ts title="compile.ts"
import { defineVars, Style } from 'zyzz'
import { Css } from 'zyzz/web'

const base = defineVars({
  color: { foreground: { light: '#171717', dark: '#fafafa' } },
})
const styles = Style.define({ card: { color: base.color.foreground } })
const output = Css.compile({ styles, vars: { base } })

const markup = `<section class="${output.vars.base}"><article class="${output.classes.card}">Account</article></section>`
```

`output.css` contains the stylesheet. `output.vars.base` and `output.classes.card` contain the classes used above. For multi-file source linking and library packaging, use [Graph.compile](https://github.com/wevm/zyzz/blob/main/docs/api/compiler/Graph/compile.md).
